28 Reading and Writing

A program is more useful when it can take something in and leave something behind: lines typed at a keyboard or sent down a serial line, words on the command line, files on a disk. This chapter covers all three, and JSON, the text that programs hand each other. print has been with us since the first page.

To Write Gives
read a line typed input(), input("Name: ") str or none
read the command line program.arguments() list[str]
read the environment program.environment(name) str or none
write on the error stream program.warn(text) nothing
end the program now program.exit(code) nothing
read a file files.read(path) str
write a file files.write(path, text) nothing
add to a file files.append(path, text) nothing
ask if a file is there files.exists(path) bool
remove a file files.remove(path) nothing
read a file as bytes files.read_bytes(path) list[u8]
write bytes to a file files.write_bytes(path, bytes) nothing
list a folder files.list(folder) list[str]
make a folder files.make_folder(path) nothing
put a path together files.join(first, second) str
read a file in pieces files.read_from(path) files.Reader
write a file in pieces files.write_to(path), files.append_to(path) files.Writer

28.1 print

print shows its values on one line, with a space between them, and ends the line. Text is shown as it is; inside a list, it is shown in quotes. To lay a line out exactly, build it with an f string (Text):

let volts = 3.3
print("supply", volts, ["a", 1])
print(f"supply={volts:.2f}V")
print()
print("after an empty line")
supply 3.3 ["a", 1]
supply=3.30V

after an empty line

28.2 Reading lines: input

input() reads the next line, without its line end. Given a question, it prints the question first and stays on that line. When there are no more lines, it gives none: at a keyboard that is Ctrl-D (Ctrl-Z then Enter on Windows), and for a file sent in with < it is the end of the file.

let name = input("Name: ")
if name is none {
    print("nobody there")
} else {
    print(f"Hello, {name}!")
}
Name: Hello, Ada!

Here the line Ada was sent in rather than typed, so it does not appear after the question as it would at a keyboard.

Because the answer may be none, it must be asked about before it is used as text (Values That May Be Missing). A loop that reads every line breaks on none, and after that the checker knows the line is a str:

var total = 0
while true {
    let line = input()
    if line is none {
        break
    }
    try {
        total += int(line.strip())
    } except ValueError {
        print("not a number:", line)
    }
}
print("total", total)
not a number: fast
total 49

Here the program was given four lines. Run it yourself and type them, or put them in a file and send it in: zeno run total.zeno < numbers.txt.

Python’s input() raises an error at the end of the input, so a loop that reads everything needs a try. none is the answer "there is no line", and the type makes sure the program handles it. (Decision 6.18.)

On a board, a firmware C library usually ties the input to a serial line, and then input() reads a line from the serial port.

28.3 The command line

program.arguments() gives the words written after the file, as a list of text. The program’s own name is not in it, so the first word is [0]:

greet.zeno

import program

let names = program.arguments()
if len(names) == 0 {
    print("usage: zeno run greet.zeno <names>")
}
for name in names {
    print("hello,", name)
}
hello, Ada
hello, Grace

With zeno run, every word after the file belongs to the program, even one that looks like an option of Zeno’s; Zeno’s own options go before the file: zeno run --vm greet.zeno Ada. A compiled program gets the same list from the words after its name: ./greet Ada Grace.

28.4 Ending, warning, and the environment

A program that other programs call says how it went with a number when it ends: 0 if all went well, anything up to 255 if not. A script reads that number with &&, || or $?. program.exit(code) ends the program there with that number. It is not an error, so no try stops it. program.warn writes a line on the error stream, which the shell keeps apart from what print prints, so a complaint does not end up in a file the output was sent to:

hello-all.zeno

import program

let names = program.arguments()
if len(names) == 0 {
    program.warn("usage: zeno run hello-all.zeno <names>")
    program.exit(2)
}
for name in names {
    print("hello,", name)
}
usage: zeno run hello-all.zeno <names>

A number outside 0 to 255 is a ValueError: on Linux, exit(256) would arrive as 0, a failure that looks like a success.

program.environment(name) reads the environment the program was started in, the names and text a shell sets, such as HOME. It gives none for a name that is not set, which the program must look at before it uses the text:

import program

let home = program.environment("HOME")
if home is none {
    print("no home folder")
} else {
    print("home is", home)
}

A firmware build refuses program.environment: a board has no environment. Chapter 34 of docs/decisions.md gives the reasons for all three.

28.5 Files

import files

files.write("shopping.txt", "milk\neggs\n")
files.append("shopping.txt", "bread\n")
print(files.read("shopping.txt").lines())
print(files.exists("shopping.txt"))
files.remove("shopping.txt")
print(files.exists("shopping.txt"))
["milk", "eggs", "bread"]
true
false

A file is read whole, as one str, and written whole. There is no open and no close, so there is nothing to forget to close. write makes the file, or empties it first; append makes it, or adds to its end.

write and append put down exactly the text they are given. A program that wants lines ends each with "\n", and reads them back with lines(), which knows both kinds of line end, so a file from Windows reads the same.

Opening and closing is a pair that every program must get right on every path, errors included, and a file left open is a classic leak. Reading and writing whole files covers what most programs do, with no pair to get wrong. A large file, read in pieces, needs a file that stays open; that is the next section but one, where the pair is kept by the end of a block and not by the program. (Decisions 6.12, 6.13 and 59.6.)

When a file cannot be used

A file that cannot be used raises a FileError, with a message that says why:

What happened The message
nothing is at the path there is no file `notes.txt`
it is a folder, or may not be read cannot read `notes.txt`
it is not text `notes.txt` does not hold text
it cannot be made or written cannot write `notes.txt`
it cannot be removed cannot remove `notes.txt` 
import files

function first_line(path: str) -> str raises FileError {
    let lines = files.read(path).lines()
    if len(lines) == 0 {
        return ""
    }
    return lines[0]
}

try {
    print(first_line("settings.txt"))
} except FileError as e {
    print("no settings:", e.message)
}
no settings: there is no file `settings.txt`

A missing file is not a mistake in the program: no check the program could make beforehand rules it out, since another program may remove the file in between. So FileError can always be caught, even in a firmware build where other errors stop the program. A function that uses a file says raises FileError, or catches it. (Decision 6.14.)

A file holds text

files.read gives a str, and a str is characters, so the file must be UTF-8 text. A picture or any other bytes are refused with a FileError.

Bytes

A file that is not text, such as a firmware image or a record a board wrote, is read with files.read_bytes. It gives every byte of the file, as it is, in a list[u8]: each byte is a number from 0 to 255, and the list does all a list does. files.write_bytes makes a file, or replaces what it held, with one byte for each item:

import files

let frame: list[u8] = [0x7E, 0x01, 0x00, 0xFF]
files.write_bytes("frame.bin", frame)

let back = files.read_bytes("frame.bin")
print(len(back), back)
var sum = 0
for byte in back {
    sum = (sum + byte) % 256
}
print(sum)

files.write("name.txt", "é")
print(files.read_bytes("name.txt"))
files.remove("frame.bin")
files.remove("name.txt")
4 [126, 1, 0, 255]
126
[195, 169]

The last lines show that text is stored as UTF-8: one é is two bytes. The list given to write_bytes is a list[u8], so every item fits in a byte; a number written out that does not, such as 256, is refused before the program runs, and a list[int] is refused too, because it could hold anything. Write [u8(n) for n in numbers] to say where the check is made. The errors are those of files.read: no file, or one that cannot be read. (Decision 36.1.)

28.6 Folders

files.make_folder makes a folder, and every folder above it that is not there yet. files.list gives the names in a folder, and files.join puts a folder and a name together into a path:

logs.zeno

import files

let day = "logs/2026/november"
files.make_folder(day)
files.make_folder(day)
files.write(files.join(day, "20.txt"), "temp 23.5\n")
files.write(files.join(day, "9.txt"), "temp 21.0\n")
files.write(files.join("logs/2026", "Notes.txt"), "calibrated\n")

print(files.list("logs/2026"))
for name in files.list(day) {
    let path = files.join(day, name)
    print(path, files.read(path).strip())
}
["Notes.txt", "november"]
logs/2026/november/20.txt temp 23.5
logs/2026/november/9.txt temp 21.0

Making a folder that is already there is no error: what counts is that there is a folder at the path at the end. So a program can make its folders each time it starts, without asking first. Something else in the way, such as a file, is a FileError.

files.list gives the names of everything in the folder, files and folders alike, as a list[str]. A name is only the last part of the path, "20.txt" and not "logs/2026/november/20.txt", and files.join puts the two back together. To tell a folder from a file, ask files.exists, which is true only for a file.

The list is sorted in the order < gives two texts, by the numbers of the characters. So "20.txt" comes before "9.txt", since the character 2 comes before 9, and "Notes.txt" before "november", since capitals come before small letters. A program that wants another order sorts the list itself.

A system gives the names in a folder in an order of its own, and not the same one on Linux, on Windows or on a board’s card. A program that printed them as they came would print something different from one machine to the next, and a test of it could not be written once. The order a person would sort in, with "9" before "10", depends on a language and on the machine’s settings. The order of < is the same everywhere. (Decision 59.20.)

files.join puts one / between the two parts, whatever their ends hold. An empty first part is no folder, and the second comes back as it is:

paths.zeno

import files

print(files.join("logs", "today.txt"))
print(files.join("logs/", "/today.txt"))
print(files.join("", "today.txt"))

try {
    print(files.list("no-such-folder"))
} except FileError as e {
    print(e.message)
}
files.write("notes.txt", "")
try {
    files.make_folder("notes.txt/old")
} except FileError as e {
    print(e.message)
}
files.remove("notes.txt")
logs/today.txt
logs/today.txt
today.txt
there is no folder `no-such-folder`
cannot make the folder `notes.txt/old`

The path uses / on Windows too, which every system Zeno runs on takes, so a program that prints a path prints the same text on every machine. join does not look at the disk, and takes two parts only: for three, write files.join(files.join(a, b), c). A board has no folders, so there files.list and files.make_folder raise a FileError, which the program can catch; files.join works anywhere. There is no way yet to remove a folder. (Decisions 59.21 to 59.23.)

28.7 A file in pieces

files.read reads a whole file into one text. A log of a gigabyte, or a file that grows while the program runs, wants a line or a few bytes at a time. files.read_from opens a file to be read in pieces, and files.write_to one to be written so:

errors.zeno

import files

files.write("big.log", "boot\nerror: no card\nready\nerror: low battery\n")

let source = files.read_from("big.log")
let errors = files.write_to("errors.log")

for line in source {
    if line.starts_with("error") {
        errors.write(line + "\n")
    }
}
print(files.read("errors.log"))
error: no card
error: low battery

errors.log was read while errors was still open, and it held both lines already: every write hands its text to the system before it gives back, so a write that cannot be done is a FileError at that write, where it can be caught. There is no close. A files.Reader and a files.Writer are resources (Ownership), so the file is closed when the let that holds it, or the parameter that took it, ends: at the end of its block, at return or break, or as an error goes past. Here that is the end of the program.

What a reader and a writer can do:

Write Does
reader.read_line() the next line without its line end, or none after the last
reader.read_bytes(count) up to count bytes, as a list[u8]
for line in reader each line in turn
writer.write(text) writes the text, and adds no line end
writer.write_bytes(bytes) writes the bytes

files.append_to writes after what the file already holds, and makes the file if it is not there. A line ends at "\n", and a "\r" just before it goes with it, as lines() reads it. In a for the loop holds one line at a time, and after a break the reader goes on from where it stopped. The reader must have a name: for line in files.read_from(path) is refused, because nothing would own the file to close it.

The end of a file is where it ends at that moment. A read that found the end looks again the next time, so a reader follows a file that this program, or another, is still writing:

grow.zeno

import files

let out = files.write_to("grow.log")
let source = files.read_from("grow.log")
print(source.read_line())
out.write("one\n")
out.write("two, still being written")
print(source.read_line())
print(source.read_line())
print(source.read_line())
none
one
two, still being written
none

What is there without a line end is given as a line, as the last line of any file is. The reader does not wait for more: when nothing new is there it gives none, and the program decides when to look again.

A program cannot make a reader itself, files.Reader(...), nor read from a writer or close either by hand; to close one sooner, give it to a function that takes it. With no collector a line is built in the text room, as input() builds one, so a line longer than the room stops the program with the room’s message; read_bytes takes its list from the pool instead. A FileError that nothing catches names a line of library/files.zeno, where the reader is written in Zeno, and its message names the file.

An open file is the pair this chapter kept away from: open and close, right on every path. A resource keeps the pair for the program: the close is at the end of the block that holds the file, which the reader can see, and an error cannot jump over it. Writing each piece through to the system at once means an error comes at the write that caused it, where the program can catch it, and not at a close where it would have nowhere to go. The reader and writer are written in Zeno over six small built-ins, so a program that never reads a file in pieces carries none of it. (Decisions 59.6 and 59.7; new in 0.8.)

28.8 A worked example: a log book

This program keeps a log of readings in a file. Each run adds the readings given on the command line, then prints every reading so far and their average:

logbook.zeno

import files
import program

let path = "readings.txt"

for word in program.arguments() {
    try {
        let value = float(word)
        files.append(path, f"{value}\n")
    } except ValueError {
        print("skipped:", word)
    }
}

var values: list[float] = []
if files.exists(path) {
    for line in files.read(path).lines() {
        values.append(float(line))
    }
}
print(len(values), "readings:", values)
if len(values) > 0 {
    print(f"average {sum(values) / float(len(values)):.2f}")
}
$ zeno run logbook.zeno 21.5 22.0
2 readings: [21.5, 22.0]
average 21.75
$ zeno run logbook.zeno 23.5
3 readings: [21.5, 22.0, 23.5]
average 22.33

28.9 JSON

Programs hand each other text in one format more than any other: JSON. A server answers in it, and a program keeps its settings in it. The json module reads it and writes it, with two functions: json.parse(text) gives the value the text describes, and json.write(value) gives a value as JSON, on one line.

settings.zeno

import json

let text = "{\"name\": \"pump 2\", \"limit\": 80, \"alarms\": [\"high\", \"dry\"]}"
let settings = json.parse(text)
let name: str = settings["name"]
let limit: int = settings["limit"]
print(name, limit + 5)
for alarm in settings["alarms"] {
    print(alarm.upper())
}
pump 2 85
HIGH
DRY

Each kind of JSON value becomes a value Zeno has: an object a dict, an array a list, text a str, true and false a bool, and null none. A number with nothing after its point is an int, even written 12.0, because many programs write a whole number either way and mean nothing by it; write float(x) where a float is wanted whatever came. A member that is null is left out of the dict, since a dict holds no none: settings.get("note") is then none, as for a member that was never written.

The checker cannot know what a text that arrives later will hold, so what json.parse gives has no type it knows. Everything can be asked of it, and a mistake is found when the line runs. Say the type where a value leaves the JSON, as let limit: int does above, and the rest of the program is checked as usual. For the same reason json.parse is refused in strict mode and in a build: JSON is for zeno run and for a web page.

json.write takes the same values, and objects, which it writes field by field in the order the class declares them. That is how a program writes JSON with text in one member and a number in the next: a class says which, and the checker holds every object to it.

order.zeno

import json

class Line {
    item: str
    count: int
}

class Order {
    who: str
    lines: list[Line]
    note: str or none
}

print(json.write(Order("Ada", [Line("tea", 2), Line("milk", 1)], none)))
print(json.write(["volts": 3.3, "amps": 0.5]))
{"who":"Ada","lines":[{"item":"tea","count":2},{"item":"milk","count":1}],"note":null}
{"volts":3.3,"amps":0.5}

A quantity is refused, because JSON has no units and a reader could not tell that 3.3 was volts: write the number, and put the unit in the name, as above. Text that is not JSON raises a ValueError.

print writes a line. input() reads one, and gives none when there are no more. program.arguments() gives the words after the file. files.read, write, append, exists and remove work on whole files of text, and every one but exists may raise a FileError, which can always be caught. files.read_bytes and write_bytes work on a file as its bytes, in a list[u8]. files.list gives the names in a folder, sorted, and files.make_folder makes one; files.join puts a path together. files.read_from, write_to and append_to open a file to be read or written in pieces, and it is closed when its owner ends. json.parse and json.write read and write JSON.

  1. Write a program that counts the lines, words and characters of the text sent to it with <.

  2. Write copy.zeno, which copies the file named by its first argument to the file named by its second, and says clearly what is wrong when it is given the wrong number of words.

  3. Keep a counter in a file: each run reads it, adds one, writes it back, and prints it. What should the first run do?

  4. Try to read a picture with files.read and read the message. Then read it with files.read_bytes, and print its first eight bytes. A PNG begins 137, 80, 78, 71, 13, 10, 26, 10.

  5. Write tree.zeno, which prints the names in a folder, and the names inside each folder in it, indented. Tell a folder from a file with files.exists.

  6. Keep the counter as JSON instead, {"runs": 3}, with json.parse and json.write.
