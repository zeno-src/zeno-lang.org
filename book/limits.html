G What Zeno Does Not Have Yet

Before version 0.1, every decision in docs/decisions.md was read again, and thirty were answered "a limit of 0.1": the thing is left out of this version, and a program that asks for it is told so. Later versions have taken some of them off the list, and what follows is what is still left out. Each can be added later without changing what any program written now means. The numbers are the decisions, for anyone who wants the argument.

G.1 On a board

Inputs.

A pin can be read (input_pin, 45), a serial port used (serial, 46), a voltage read (analog_pin, 47) and a PWM signal made (pwm_pin, 48), but nothing presses a button or feeds a voltage under zeno run (45.5), and none of it has been tried on a real board. A PWM pin cannot be asked its duty or given a new frequency (48.6). A board keeps sixteen tickers and none is given back (ticker, 49.5). An interrupt counts edges (interrupt, 50), and no function of the program runs inside one (50.3); nor can a program wait for the first of several.

G.2 Numbers

A u64 in a few places.

A u64 is not yet a key of a dict, an index, a count for range, or something json.write can write; int( ) makes one an int (42.10).

A list of a fixed length takes a block.

A list[u8, 64] in a build with no collector is a block from the pool, as any list is, though its size is known (36.5).

Units of a program’s own.

Units make units only from a closed list (V * A is W, 1 / 2 ms is Hz), and a program cannot name a unit of its own, or use charge (mAh) or speed yet (43.6).

G.3 Types

Unions.

Only or none can follow a type: int or str is refused (1.13). An enum that carries data does the same work.

One bound for a type.

A type parameter asks for at most one interface, such as [T is Ordered], not two at once, and a class cannot be Ordered until it can say what < means for its objects (58.3).

A generic as a value.

A generic function, or a case of a generic enum, cannot be kept as a value, a method cannot have type parameters of its own, and the types cannot be written at a call (3.16e, 58.1).

Several values in a for

(for q, r in pairs()), and a default for one of several results (57.6).

A resource lives only in a let or a parameter:

not in a field, a list, a dict, or none, an enum or a type parameter, and a release cannot raise (59.2).

G.4 The library

A file’s name on Windows.

In a program built through C or LLVM on Windows, a file’s name goes through the system’s code page, as fopen takes it, so a name with letters that page lacks cannot be opened there; zeno run takes any name (59.20).

Files in pieces.

A reader cannot go back or say where in the file it is, does not wait for a file to grow, and reads only UTF-8; each write goes to the system at once (59.6).

The methods of text and lists written in Zeno.

A part of the library is written in Zeno itself: math.hypot, the hyperbolic functions, math.gcd, math.clamp and the module random (33.1). The methods of text and lists are still built into the compiler (6.10). And random has no seed from the machine: a program gets the same numbers on every run until it calls random.seed (33.8).

G.5 Libraries of other languages

A function of Zeno cannot be given to another language

: not as a callback of C, a block of Ruby, a lambda of LINQ or a sort key of Python (26.12, 44.9).

The seven that run beside Zeno

(import python and its like) are for zeno run and zeno test. Every build refuses them (26.12).

From C:

a struct given whole, a function with ..., the address of a variable, and declarations read from a header by themselves are not there (44.9). --llvm and --target refuse import c, and it has not been run with a cross-compiler’s own libraries or on a board.

An inline block

is of C, Python or JavaScript, and not of Ruby, PHP, Lua, C#, C++ or assembly by itself. A block of C cannot name a library it needs, and Zeno sees its functions and not its constants. --llvm and --target refuse a block, and every build refuses one of Python or JavaScript (61.11, 61.19).

A call the C compiler can work out.

A built program’s m.cbrt(27.0) is worked out by GCC before the program runs, rounded exactly, where zeno run asks the library: the two can differ in the last digit.

G.6 Builds

One file at a time.

A build compiles the whole program at once (7.11).

A board by its name.

zeno build --board takes the folder of a board, which today is in a copy of Zeno’s repository or written by you; it does not load the program onto the board, and a build for a board has no collector (51.9). The two boards that come with Zeno are one emulated chip.

–memory on a board that prints by itself.

The report is written as the C library ends a program, and such a board has no C library under the program (52.8).

A NaN with decimals in a minimal build for a computer.

There {x:.2f} is printf’s own, so a float that is not a number is shown as the C library writes it, nan. Every other build prints NaN, as zeno run does (53.8).

A compiler that is neither GCC nor Clang.

It gets the checks in plain C (chapter 55), and tcc builds every example so. No program has been built by IAR’s, Keil’s or a chip maker’s compiler. A firmware build with a collector cannot be built by such a compiler, and its C says so (55.5).

setjmp in an ordinary build.

An ordinary build uses it for try, and a firmware build does not use it at all (5.11l, 12.8).

G.7 Firmware and no collector

What a build with no collector refuses by design.

Replacing what a field holds through a parameter that only looks, taking an item out of a list a for walks (5.15e), keeping an item that [ ] only looks at, and a kept function that uses a var from outside it. Each is refused with the reason, and the table of docs/no-collector.md lists them all (56.17).

Swapping two items a list owns,

xs[i], xs[j] = xs[j], xs[i] on a list of lists or objects with no collector: each item is only looked at there (57.6).

G.8 Interfaces

Functions of an interface

have no type parameters and cannot be private (10.5), and a default for one of their parameters is a plain value (58.20).

An interface that is another interface

(10.10, 58.23).

G.9 The web

Only what the module has.

No images drawn on a canvas, no curves, no touch with more than one finger, and no address bar of its own (16.13).

An interpreter in a page.

Every page carries zeno.wasm and runs at the speed of zeno run. A page compiled through C or LLVM, small and fast, is left for later (14.1).

A simulated page reads plain selectors only,

and knows no CSS (16.9).

The playground

runs one file, and has no colours in its box and no Stop button (16.12).

JSON

is read into dicts and lists, not straight into a class, and is not in compiled programs (18.5).

G.10 Tools

Going to a field.

The language server shows the type of a field, but cannot yet jump to where it was declared (17.4).

assert is only for tests

(10.21).

G.11 Not limits

Three things are not on this list, because they are decided: Zeno has no inheritance, no second way to write a function, and no second name for a module. The reasons are in Why Zeno Is as It Is.
