9 Lists

A list holds several values in order. It can grow and shrink, and each of its items has a position, counted from 0.

9.1 Making a list and reading it

let primes = [2, 3, 5, 7]
print(primes, len(primes), primes[0], primes[3])
print([], [[1, 2], [3]])
[2, 3, 5, 7] 4 2 7
[] [[1, 2], [3]]

The type of a list says what its items are: primes is a list[int]. Zeno works it out from the items, or you write it, which you must do for an empty list that has nothing yet to work it out from:

let names: list[str] = []
let grid: list[list[int]] = [[1, 2], [3, 4]]
print(names, grid[1][0])
[] 3

A position outside the list is an IndexError, and so is a negative one (Text gives the reason):

let primes = [2, 3, 5, 7]
print(primes[4])
error: uncaught IndexError: index 4 is out of range for a list of length 4
 --> main.zeno:2:7
  |
2 | print(primes[4])
  |       ^

9.2 Changing a list

let xs = [3, 1, 2]
xs.append(4)           # at the end
xs.insert(0, 9)        # at position 0, moving the rest up
print(xs)
xs[1] = 30             # replace the item at position 1
print(xs)
let last = xs.pop()    # take out the last item, and give it
let first = xs.pop(0)  # take out the item at position 0
print(last, first, xs)
xs.clear()             # take out everything
print(xs)
[9, 3, 1, 2, 4]
[9, 30, 1, 2, 4]
4 9 [30, 1, 2]
[]

All of these change the list itself, which is why xs can be a let: the name always means the same list, while what the list holds changes. Values and Variables has the rule.

Every item must be of the list’s type:

let xs = [1, 2]
xs.append("three")
error: an item added to this list should be int, but this is str
 --> main.zeno:2:11
  |
2 | xs.append("three")
  |           ^

1 error found. Nothing was run.

9.3 Every method of a list

Method Does
append(x) puts x at the end
insert(at, x) puts x at position at, moving the rest up
pop() takes out the last item, and gives it
pop(at) takes out the item at at, and gives it
clear() takes out every item
reverse() turns the list round, where it is
sort() puts numbers or text in order, smallest first, where it is
find(x) the position of the first item equal to x, or none
slice(from, to) a new list of the items from from up to, not including, to
slice(from) a new list of the items from from to the end
join(sep) for a list of text: one text, with sep between the items
map(f) a new list of f of each item
filter(f) a new list of the items for which f is true
reduce(f, start) the items folded into one value with f, starting from start

Beside them stand the functions len(xs), sum(xs), min(xs) and max(xs), the operator x in xs, and + to join two lists into a new one.

let numbers = [5, 3, 9, 1]
numbers.sort()
print(numbers, numbers.find(9), numbers.find(4), 3 in numbers)
numbers.reverse()
print(numbers, numbers.slice(1, 3), numbers + [0])
print(["pear", "fig", "apple"].join(", "))
print(sum(numbers), min(numbers), max(numbers))
[1, 3, 5, 9] 3 none true
[9, 5, 3, 1] [5, 3] [9, 5, 3, 1, 0]
pear, fig, apple
18 1 9

What there is no method for

Some methods that other languages have are left out, because Zeno already says the thing in one short expression:

In other languages In Zeno
xs.contains(x) x in xs
sorted(xs) let ys = xs.slice(0), then ys.sort()
xs.remove(x) xs.find(x), then xs.pop(at)
xs.extend(ys) xs += ys
xs[1:3] xs.slice(1, 3)

A method gets into the library only if most programs in the big languages use it and Zeno cannot already say it in one short expression. That keeps one way to write each thing. (Decision 6.1.)

sort and reverse change the list

sort and reverse work where the list is and give back nothing. To keep the old order, sort a copy, which slice(0) makes:

let readings = [5, 3, 9, 1]
let in_order = readings.slice(0)
in_order.sort()
print(readings, in_order)
[5, 3, 9, 1] [1, 3, 5, 9]

sort knows how to order numbers and text, which have one order that nobody has to be told. Anything else it refuses, with the reason:

let flags = [true, false]
flags.sort()
error: `sort` puts numbers or text in order, smallest first, and this is list[bool]. There is no one order for those items, so give `sort` a function that says what each is ordered by, as in `people.sort(age_of)`
 --> main.zeno:2:1
  |
2 | flags.sort()
  | ^

1 error found. Nothing was run.

sort with a function

A list of objects has no order of its own. A program says which order it wants by giving sort a function that takes one item and gives what the item is ordered by, a number or text: its key. The function comes in Functions as Values; here it is written in place:

class Person {
    name: str
    age: int
}

let people = [Person("Ada", 36), Person("Bo", 20), Person("Cy", 36)]
people.sort(function(person: Person) -> int { return person.age })
for person in people {
    print(person.name, person.age)
}
Bo 20
Ada 36
Cy 36

The function is called once for each item, before anything moves. Items with the same key stay in the order they were: Ada was before Cy, both are 36, and Ada is still first. So sorting by name and then by age gives people in order of age, and by name within an age. For biggest first, give the key with a minus, return 0 - person.age.

The function is not asked which of two items comes first, as a sort is in C or JavaScript. A function that takes two items is refused, with the reason. (Decision 21.1.)

A new list is new memory, which a program on a small board may not want to spend, and a method that gives the list back invites let ys = xs.sort(), where it is not clear whether xs changed. sort is heapsort in every engine: it needs no second list, never calls itself, and is never slow, which is what firmware wants. (Decisions 6.5 and 6.6.)

find, and taking out by value

find gives a position or none. To take out an item by its value, find it first, and say what happens when it is not there:

let names = ["Ada", "Grace", "Alan"]
let at = names.find("Grace")
if at is not none {
    names.pop(at)
}
print(names)
["Ada", "Alan"]

9.4 Joining lists

+ makes a new list from two, and += adds a list to the end of a list variable. Both lists must hold the same kind of thing:

var log: list[str] = ["start"]
log += ["read", "write"]
print(log + ["stop"])
["start", "read", "write", "stop"]
let xs = [1, 2]
print(xs + ["a"])
error: `+` joins two lists that hold the same kind of thing, and these are list[int] and list[str]
 --> main.zeno:2:7
  |
2 | print(xs + ["a"])
  |       ^

1 error found. Nothing was run.

* with a number repeats a list: the list comes first, and the result is a new list. It is how a buffer of zeros is made:

print([0] * 4, [1, 2] * 2)
[0, 0, 0, 0] [1, 2, 1, 2]

A list of lists cannot be repeated, because every row would be one and the same row, and a change to one would show in all of them. A comprehension makes each row: [[0] * 3 for i in range(3)]. A count below zero is a ValueError. (Decision 36.3.)

9.5 Comprehensions

A comprehension builds a new list from another in one line: an expression for each item, a for, and if you like an if that keeps only some items:

let numbers = range(1, 11)
print([n * n for n in numbers])
print([n for n in numbers if n % 3 == 0])
print([word.upper() for word in ["a", "b"]])
[1, 4, 9, 16, 25, 36, 49, 64, 81, 100]
[3, 6, 9]
["A", "B"]

It reads the way it would be said: "n times n, for each n in numbers".

9.6 map, filter and reduce

The same work can be done by handing a function to a method. map applies it to each item, filter keeps the items it says true for, and reduce folds the list into one value:

function square(n: int) -> int {
    return n * n
}
function is_even(n: int) -> bool {
    return n % 2 == 0
}
function add(total: int, n: int) -> int {
    return total + n
}

let numbers = [1, 2, 3, 4, 5, 6]
print(numbers.map(square))
print(numbers.filter(is_even))
print(numbers.reduce(add, 0))
print(numbers.filter(is_even).map(square).reduce(add, 0))
[1, 4, 9, 16, 25, 36]
[2, 4, 6]
21
56

The last line reads left to right, in the order things happen: take the numbers, keep the even ones, square them, add them up.

As methods, map, filter and reduce read left to right. As plain functions, the same chain is reduce(add, map(square, filter(is_even, numbers))), which has to be read from the inside out. (Decision 3.6b.)

A function can also be written in place, with no name. Functions as Values covers that.

9.7 Two names, one list

A list is not copied when it is given another name, passed to a function or put in another list. Every name sees the one list:

function add_reading(readings: list[float], r: float) {
    readings.append(r)
}

let mine = [20.5]
let also_mine = mine
add_reading(also_mine, 21.0)
print(mine)
[20.5, 21.0]

When you want a separate list, make one: xs.slice(0) copies the whole list.

Sharing is what Python, Java and JavaScript programmers expect, and it is the cheapest thing to do. In an ordinary build a garbage collector makes it safe; a build with no collector gives each list one owner instead, and Building with No Collector explains how. (Decision 3.10.)

9.8 Equal lists

Two lists are equal when they have equal items in the same order:

print([1, 2] == [1, 2], [1, 2] == [2, 1])
true false

9.9 A list of a fixed length

list[u8, 64] is a list that always has 64 items: a buffer, a frame, a block, whose size is known when the program is written. It gets a list of exactly that many items, and the count is checked before the program runs:

var buffer: list[u8, 8] = [0] * 8
buffer[0] = 0x7E
print(buffer, len(buffer))
[126, 0, 0, 0, 0, 0, 0, 0] 8

Everything that leaves the length as it is works as on any list. append, pop, insert and clear are refused, and so is a position written as a number that is past the end:

var buffer: list[u8, 8] = [0] * 8
buffer.append(1)
error: `append` would change how many items this list has, and a list of a fixed length always has 8. Give an item a new value instead, as in `list[0] = 7`
 --> main.zeno:2:1
  |
2 | buffer.append(1)
  | ^

1 error found. Nothing was run.

A function whose parameter is an ordinary list[u8] can be given one, if nothing in the function could change how many items the list has. The checker reads the function to know, and when something could, the message names the line:

function total(data: list[u8]) -> int {
    var sum = 0
    for b in data {
        sum += b
    }
    return sum
}

let frame: list[u8, 4] = [0x7E, 1, 2, 0x7F]
print(total(frame))
256

The length is part of the type, as in C’s uint8_t buf[64] and Rust’s [u8; 64], because a mistake about it is then found before the program runs, not as an IndexError on a board. It is written as one more thing in the [ ] of list rather than as a new kind of list, because it is a list: one that cannot grow. (Decision 36.4.)

A list holds values of one type, in order, from position 0. It grows with append, insert and +=, shrinks with pop and clear, and is ordered with sort and reverse, all in place. find, slice, join, map, filter and reduce give new values. Comprehensions build lists in one line, and [0] * 64 repeats one. A list is shared, never copied without being asked. A list[u8, 64] always has 64 items.

  1. Write function median(values: list[float]) -> float that does not change the list it is given.

  2. Take every second item of a list with a comprehension and range.

  3. Remove every 0 from a list of numbers, first with a loop and pop, then with filter. Which is easier to get right, and why?

  4. Write a list of lists that is a 3 by 3 grid of zeros, set the middle to 1, and print it row by row.

  5. Make a ring buffer: a list[int, 4], a position that goes round with % 4, and a loop that writes ten numbers into it. Which four are left at the end?
