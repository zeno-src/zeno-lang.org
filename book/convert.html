26 A File of Python Written as Zeno

The block of the last chapter keeps code as it was written. Since 0.9 zeno convert goes the other way: it takes a whole file of Python and writes it again as Zeno. What it can say in Zeno it says in Zeno, and what it cannot it leaves as Python, in an inline python block that the Zeno calls. So what it writes always runs, and prints what the Python printed.

The one promise is that what is written is never silently wrong. Where Zeno would do even a little otherwise than Python, the converter either says so in a comment or keeps the line as Python.

26.1 A first file

Here is a small till, in Python:

shop.py

# A till: prices, a basket, and a receipt.
import textwrap

PRICES = {"tea": 2.5, "cake": 3.0, "jam": 1.25}


def line_total(item, count):
    return PRICES[item] * count


def receipt(basket):
    lines = []
    total = 0.0
    for item, count in basket.items():
        cost = line_total(item, count)
        total += cost
        lines.append(f"{item:<6} x{count}  {cost:6.2f}")
    lines.append(f"{'total':<9} {total:6.2f}")
    return lines


basket = {"tea": 2, "jam": 3}
basket["cake"] = 1
for line in receipt(basket):
    print(line)
words = sorted(word.upper() for word in basket)
print(", ".join(words))
note = textwrap.fill("Thank you for shopping with us, and come back soon.", width=24)
print(note)

One command writes shop.zeno beside it, and says what it did with each piece of the file:

$ zeno convert shop.py
Wrote shop.zeno from shop.py.
  11 pieces: 10 written as Zeno, 1 kept as Python.

  Where Zeno does otherwise than Python (2 lines; each kind has a `# convert:` comment at its first):
    a value is shown as Zeno shows it: line 29
    `upper` and `lower` change a to z only: line 26

  Kept as Python, in the `inline python` block:
    line 2, `import textwrap`: `textwrap` is a module of Python, and what uses it reaches it through the block

  Run it with `zeno run shop.zeno`. It prints what `python3 shop.py` prints,
  but for the notes above.

This is the Zeno it wrote:

$ cat shop.zeno
# Written from shop.py by `zeno convert`.

import python

let py = inline python {
    import textwrap
}

# convert: Python's `sorted`, a copy of a list with the smallest first.
function sorted[T is Ordered](items: list[T]) -> list[T] {
    let copy = items.slice(0)
    copy.sort()
    return copy
}

# A till: prices, a basket, and a receipt.

let PRICES = ["tea": 2.5, "cake": 3.0, "jam": 1.25]

function line_total(item: str, count: int) -> float {
    return PRICES[item] * count
}

function receipt(basket: dict[str, int]) -> list[str] {
    let lines: list[str] = []
    var total = 0.0
    for item, count in basket {
        let cost = line_total(item, count)
        total += cost
        lines.append(f"{item:<6} x{count}  {cost:6.2f}")
    }
    lines.append(f"{'total':<9} {total:6.2f}")
    return lines
}

let basket = ["tea": 2, "jam": 3]
basket["cake"] = 1
for line in receipt(basket) {
    print(line)
}
# convert: `upper` and `lower` change a to z only. Python changes every letter
# that has a capital.
let words = sorted([word.upper() for word in basket])
print(words.join(", "))
let note = py.textwrap.fill("Thank you for shopping with us, and come back soon.", width=24)
# convert: Zeno shows a value its own way: `true`, `false` and `none` in small
# letters, a text inside a list, a dict or an object in double quotes, and a
# dict between `[` and `]`.
print(note)

The types came from the program itself. line_total is given a text and a whole number at its one call, and gives back a float, so it is function line_total(item: str, count: int) -> float. basket holds whole numbers under texts, so receipt takes a dict[str, int]. sorted is not a function of Zeno, so the file gets a short one at the top, with a comment that says what it is. textwrap is a library of Python that Zeno has no words for: its import stays in the block, and fill is called through it, as py.textwrap.fill.

Both print the same:

$ zeno run shop.zeno
tea    x2    5.00
jam    x3    3.75
cake   x1    3.00
total      11.75
CAKE, JAM, TEA
Thank you for shopping
with us, and come back
soon.
$ python3 shop.py
tea    x2    5.00
jam    x3    3.75
cake   x1    3.00
total      11.75
CAKE, JAM, TEA
Thank you for shopping
with us, and come back
soon.

26.2 Pieces, and what becomes of each

The converter cuts the file into pieces: the statements that begin at its left margin. A def with its body is one piece, so is a class, a for loop at the top of the file, or one line such as basket["cake"] = 1. Each piece ends in one of three states:

State What is written
Zeno lines of Zeno that mean what the piece meant
Zeno with a note the same, with a # convert: comment where Zeno does something a reader of Python would not expect
Kept the piece as it was written, in the inline python block

A piece is cut whole, because a piece is what a reader sees as one thing, and keeping one whole keeps its meaning: nothing inside it is changed.

26.3 What is kept

Some of Python is not in Zeno: a lambda, a function inside a function, yield, a class with a base, sort(key=...). A piece with one of these is kept, and the report says why, with the line:

$ zeno convert counter.py
Wrote counter.zeno from counter.py.
  8 pieces: 2 written as Zeno, 6 kept as Python.

  Where Zeno does otherwise than Python (2 lines; each kind has a `# convert:` comment at its first):
    a value is shown as Zeno shows it: lines 15, 19

  Kept as Python, in the `inline python` block:
    line 1, `def make_counter`: `nonlocal` is not translated yet (line 5)
    line 12, `tick = make_counter()`: `tick` is used by the piece at line 13, which is kept as Python, and Python can call only Python
    line 13, `for _ in range(3):`: `tick` holds a function and is called, which is not translated yet (line 14)
    line 17, `values = [3, 1, 2]`: `values` is used by the piece at line 18, which is kept as Python, and Python can call only Python
    line 18, `values.sort(key=lambda value: -value)`: `sort` with `key=` or `reverse=`
    line 20, `print(len(values), max(values))`: `max` of a value that only Python knows

  Run it with `zeno run counter.zeno`. It prints what `python3 counter.py` prints,
  but for the notes above.
$ cat counter.zeno
# Written from counter.py by `zeno convert`.

import python

let py = inline python {
    def make_counter():
        count = 0

        def step():
            nonlocal count
            count += 1
            return count

        return step

    def convert_step_1():
        global tick
        tick = make_counter()

    def convert_step_2():
        global _
        for _ in range(3):
            tick()

    def convert_step_3():
        global values
        values = [3, 1, 2]

    def convert_step_4():
        values.sort(key=lambda value: -value)

    def convert_step_5():
        print(len(values), max(values))
}

# `def make_counter` is kept as Python, in the block above.

py.convert_step_1()
py.convert_step_2()
# convert: Zeno shows a value its own way: `true`, `false` and `none` in small
# letters, a text inside a list, a dict or an object in double quotes, and a
# dict between `[` and `]`.
print("ticks:", py.tick())

py.convert_step_3()
py.convert_step_4()
print(py.values)
py.convert_step_5()

A kept def goes at the top of the block. A kept piece that does something, such as the loop, becomes a function of the block, convert_step_2, and the Zeno calls it where the loop was, so it runs exactly when it ran in the Python.

Some pieces are kept for what another piece became. tick holds what a kept function gave, which only Python can call, so the line that gives it its value is kept too: Python can only call Python, and a variable lives on one side. Each reason in the report says which.

The converter keeps one piece at a time. When several pieces cannot be written, it keeps the first that has a reason of its own, and tries the rest again, since a piece that could not be written a moment ago often can be once the piece it depended on has gone to Python.

26.4 What crosses between the two sides

The Zeno and the block are two sides of the bridge to Python of Libraries of Other Languages. A number, a text, a bool and none cross exactly. A value of Python’s own, such as an object a kept class made, stays in Python, and Zeno holds it as a handle. A list or a dict of Zeno is copied on its way to Python, and what Python did to its copy would not be seen. So the converter gives a function of the block only numbers, texts, bools, none, values of Python’s own, and lists or dicts written right there in the call. A line that would give it a list the Zeno holds is kept.

26.5 The notes

Each note marks a place where the Zeno does what the Python did, but prints or raises a little otherwise. The comment is written once for each kind, above the first line it applies to, and the report lists every line.

Note What is otherwise
a value is shown as Zeno shows it true, false and none in small letters, a text inside a list in double quotes, a dict between [ and ]
a very large or very small float Python’s 1e+16 is 1e16
the message of an error in Zeno’s words where Zeno raised it
an except catches more Zeno raises an error where Python raises none: a whole number past 64 bits, say
upper and lower a to z only
math.round a half goes away from zero: 2.5 to 3
a float from the first value the variable holds a float later, and a variable of Zeno has one type

26.6 What it does not promise

A program that Python stops with NameError is outside the promise: a name the converter declares before a block has the first value of its type, where Python would stop. Whole numbers past 64 bits make Zeno stop with OverflowError, so that is never silent, but int() of a float past 64 bits gives the largest whole number Zeno has. The rest is rare, and is listed in docs/convert.md.

26.7 How it is checked

Every rule is held to its word by programs of Python in tools/convert of the repository. Each is converted, run with python3 and with zeno run, and what the two print is compared; the first line of each says how many of its pieces are to be kept, so that a rule that stops working is seen even when the output is still the same. One of them is a program of 240 lines, with classes, a dataclass, dicts of objects, exceptions, f-strings and a report, and all of it but its import json is written as Zeno.

Last of all, the converter reads what it wrote with Zeno’s own checker, in the same program, before it writes the file. A piece the checker does not take is kept, with the checker’s words as the reason. Nothing Zeno would refuse is ever given out.

C is the next language zeno convert is to read, with what it cannot read left in an inline c block.
