E The zeno Command

Everything Zeno does is done by one command, zeno, followed by what to do and usually a file. This appendix lists every command and every option of version 0.1. zeno --help prints the same list.

E.1 Commands

Command What it does
zeno run f.zeno check the program, then run it. Words after the file are the program’s own arguments (Reading and Writing)
zeno check f.zeno check the program for mistakes, and run nothing
zeno build f.zeno compile to C and then to a program that runs by itself (Compiling). The C is kept beside it
zeno test run the test "name" { } blocks of a file, of every file in a folder, or of this folder when nothing is named (Testing). --only words runs only the tests with those words in their names
zeno format f.zeno lay files out the one way Zeno lays them out; several files, or a folder, can be named (The Tools)
zeno convert f.py write a file of Python again as Zeno, as f.zeno, keeping what cannot be written in an inline python block, and say what was done with each piece (A File of Python Written as Zeno). --to names the file to write, --replace writes over one
zeno convert f.c the same for a file of C, keeping what cannot be written in an inline c block (A File of C Written as Zeno)
zeno new name make a folder with a new program in it: a main.zeno, a module with a test, and a zeno.package (Packages)
zeno new --package name make a folder with a new package: modules for other programs to need, and no main.zeno
zeno fetch get the packages that the needs lines of zeno.package list, for this folder or a named one
zeno search words list the packages of the registry that have these words in their name or in what they are for; with no word, all of them
zeno publish check that the package in this folder is ready for the registry, and say how to ask the registry to take it. A version after it, zeno publish v1.2.0, says which tag
zeno registry accept for whoever keeps a registry: take a version of a package into a clone of it (Packages)
zeno tokens f.zeno show the tokens the lexer finds (Inside Zeno)
zeno parse f.zeno show the syntax tree the parser builds, with brackets around every expression
zeno join f.zeno show the one program that the file and every file it imports are joined into
zeno bytecode f.zeno show the bytecode that zeno run --vm runs
zeno playground write playground.html, a page in which Zeno programs are written and run in a browser, with nothing installed (A Program in a Web Page)
zeno lsp the language server. An editor starts it, to show mistakes as you type; you do not run it yourself
zeno --version print the version
zeno --help print the list of commands and options

E.2 Options

An option goes after the command and before the file.

Option With What it does
--strict run, check every type must be known before the program runs, as a build needs (Types, Written and Worked Out). build always works so
--vm run compile to bytecode and run that, in place of walking the tree. Same output, about twice as fast
--no-collector check check as build --no-collector would, without building
--firmware build errors travel as return values, with no setjmp (Firmware)
--no-collector build no garbage collector and no malloc: every list and object has one owner, and memory comes from a fixed pool (Building with No Collector). Turns --firmware on
--owned build, check, run one owner for every list and object and no collector, as memory owned in zeno.package says; memory grows as the program needs it (Memory)
--collector build, check, run the garbage collector, whatever zeno.package says
--release build whole numbers wrap round on overflow instead of stopping the program; every other check stays
--fast build no index check, no check of a float divided by zero or of a square root below zero, overflow with no defined result (as in C), and -O3
--minimal build the least C that runs the program: no check of any kind, only the parts of the runtime the program uses, print as printf, and -Os (Compiling; new in 0.5.2)
--board <folder> build build for a board in one step: the zeno.board in the folder names the board’s C compiler, flags, start-up files and linker script, and the program comes out as name.elf. Built with no collector. Goes with --minimal, --release, --fast and --memory (Compiling; new in 0.7)
--llvm build write LLVM IR in place of C and hand it to clang. Goes with the three options around it
--web build write a web page that runs the program: name.html beside it, or a plain page, with the program inside, as name.web.html (A Program in a Web Page). Goes with no other build option
--target build write the program in another language: js, ts, html, py, php, go, java, cs, cpp, rust or wasm (Compiling; new in 0.5), and since 0.5.2 lua, ruby, dart and kotlin
--memory build the program reports, as it ends, how much memory it used (Memory)
--check format change nothing; name the files that are not laid out, and fail if there are any
--package new make a package, not a program
--update fetch look every version up again, and not at the commits that zeno.lock pinned

E.3 What a command answers

Every command ends with an exit status, the number a shell script or a build tool reads to know how it went: 0 when all went well, and 1 when the program had a mistake, an uncaught error, a failing test, or a file that format --check would change. Messages go to the error stream, and what the program prints goes to the output stream, so zeno run f.zeno > out.txt keeps only what the program printed.

E.4 Telling the C compiler

A build writes C, and these names can be set when that C is compiled, with -D on the line of the C compiler:

Name What it sets
ZENO_BOARD a header that puts a real board under the program, in place of the simulated one: -DZENO_BOARD='"my_board.h"' (Firmware)
ZENO_BOARD_PRINTS said by such a header, with #define, when it brings the four functions that print, warn, read and stop in place of the C library (Firmware)
ZENO_POOL the size of the pool in bytes for a build with no collector, 32 768 unless set: -DZENO_POOL=25384
ZENO_TEXT_ROOM the size of the text room in bytes, for the same build
ZENO_PLAIN_C asks GCC or Clang for the checks written in plain C, which every other C compiler gets unasked (Firmware; new in 0.7)

E.5 Names in the environment

Zeno finds the other programs it needs by their usual names. A name in the environment says where another one is:

Name What it names
CC the C compiler of zeno build and of import c, in place of cc, gcc or clang
ZENO_PYTHON, ZENO_NODE the Python or the Node that import python or import node starts (Libraries of Other Languages)
ZENO_JAVA, ZENO_RUBY the same for import java and import ruby
ZENO_PHP, ZENO_LUA and for import php and import lua
ZENO_DOTNET the dotnet of import csharp
