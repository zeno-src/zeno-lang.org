1 Getting Zeno

Zeno is one program, called zeno. It checks your programs, runs them, compiles them, tests them, lays them out, and talks to your editor. This chapter puts it on your machine.

There are three ways to get it: an installer, which does everything for you; an archive that you unpack and put in place yourself; or building it from its source. The first two take a minute and need nothing installed. The third needs Rust, and gives you the compiler’s source to read beside Inside Zeno.

Zeno 0.8.0 is the current release, and everything below installs it. Its files are on the releases page of the repository:

https://github.com/zeno-src/zeno-lang/releases/latest

1.1 The installers

On Windows

Download zeno-0.8.0-windows-setup.exe from the releases page, run it, and press Next.

It is the same file for every Windows machine: it holds the zeno.exe for x86-64, 32-bit x86 and ARM, and installs the one this machine needs, into %LOCALAPPDATA%\Programs\Zeno. Nothing asks for an administrator’s password. The box that adds Zeno to the PATH is ticked, so zeno works in any terminal opened afterwards. If the machine has no C compiler or no git, two more boxes offer to install them with winget, the package manager that comes with Windows 10 and 11.

The first time it runs, Windows says Windows protected your PC. It says that of every program whose maker has not bought a certificate to sign it with. More info, then Run anyway, lets it start. The Start menu then has a Zeno folder with a Zeno Prompt, the examples, the docs, and Uninstall Zeno; Zeno can also be removed from the list of installed apps in Windows’ settings.

On macOS and Linux

One line in a terminal:

curl -fsSL https://github.com/zeno-src/zeno-lang/releases/latest/download/install.sh | sh

curl downloads a shell script of about three hundred lines, half of them comments, and sh runs it. It works out which machine this is, downloads the archive for it, checks the archive against the release’s list of checksums before unpacking anything, and puts zeno in ~/.zeno. It adds one line to your shell’s startup file to put that folder on the PATH, and offers to install a C compiler and git if they are missing. Open a new terminal afterwards, and zeno is there:

$ zeno --version

The script is meant to be read before it is trusted. To read it first, download it with curl -fsSL -o install.sh and the same address, and then run sh install.sh. Later,

sh install.sh --uninstall

takes all of it off again.

If an installer stops with a message you cannot get past, write to help@zeno-lang.org with the message and the name of your system.

1.2 With a package manager

Each release also has Zeno in the forms that the usual package managers install: a .deb for apt, a package for pacman, a snap, a flatpak, a formula for Homebrew, and the files winget reads. Each puts zeno and zeno.wasm where that system keeps programs, and each removes them again the usual way.

Each installs from its file, downloaded from the releases page:

sudo apt install ./zeno_0.8.0_amd64.deb                     # Debian, Ubuntu, Raspberry Pi OS
sudo pacman -U zeno-lang-bin-0.8.0-1-x86_64.pkg.tar.zst          # Arch
sudo snap install --classic --dangerous zeno_0.8.0_amd64.snap
flatpak install --user zeno-0.8.0-x86_64.flatpak

The .deb comes for amd64, arm64, armhf (any Raspberry Pi with a 32-bit system) and i386, and apt installs a C compiler and git beside it, because the package recommends them. pacman only names them, and installs them when asked. The snap is classic, so that zeno build can reach the C compiler the system already has. A flatpak runs in a box of its own, with its own compiler and git inside, and its command is long, so give it a short name:

alias zeno='flatpak run org.zeno_lang.Zeno'

Homebrew, on macOS or Linux, reads a formula from the Zeno repository:

brew tap zeno-src/zeno-lang https://github.com/zeno-src/zeno-lang
brew install zeno-src/zeno-lang/zeno

On Windows, winget runs the same setup program as above, with its boxes for the compiler and git left unticked, since somebody who uses winget installs those with winget too.

Installing with one word, as in sudo apt install zeno or winget install ZenoLang.Zeno, needs each manager’s own collection to list Zeno: the AUR (where its name will be zeno-lang-bin, since another program there is already called zeno), the Snap Store, Microsoft’s list for winget, and an apt repository of Zeno’s own. Those are prepared, and wait on the people who keep them. The flatpak stays a file: Zeno will not be on Flathub. Zeno is free software under the MIT licence, and each package carries the licence with it.

1.3 Downloading it by hand

The installers fetch one of ten archives, one for each kind of machine a release is built for. To do by hand what they do, pick the file for your machine from the same releases page:

Machine File
Linux on most PCs and servers (x86-64) zeno-0.8.0-linux-x86_64.tar.gz
Linux on 32-bit x86 zeno-0.8.0-linux-x86.tar.gz
Raspberry Pi 3, 4 or 5 with a 64-bit system, and ARM servers zeno-0.8.0-linux-arm64.tar.gz
Raspberry Pi 2 or later with a 32-bit system (ARMv7) zeno-0.8.0-linux-armv7.tar.gz
Raspberry Pi 1 or Zero (ARMv6) zeno-0.8.0-linux-armv6.tar.gz
Mac with Apple silicon (M1 and later) zeno-0.8.0-macos-arm64.tar.gz
Mac with an Intel processor zeno-0.8.0-macos-x86_64.tar.gz
Windows on most PCs (x86-64) zeno-0.8.0-windows-x86_64.zip
Windows on 32-bit x86 zeno-0.8.0-windows-x86.zip
Windows on ARM zeno-0.8.0-windows-arm64.zip

Inside is one folder with zeno in it (zeno.exe on Windows), and zeno.wasm beside it, which A Program in a Web Page needs. zeno is one file that needs nothing else installed: no Rust, no libraries.

On Linux and the Raspberry Pi

Unpack the file, and copy zeno into a folder that is on your PATH. ~/.local/bin is one on most systems, and needs no sudo:

$ tar -xzf zeno-0.8.0-linux-x86_64.tar.gz
$ mkdir -p ~/.local/bin
$ cp zeno-0.8.0-linux-x86_64/zeno* ~/.local/bin/
$ zeno --version
zeno 0.8.0

If the shell says zeno: command not found, that folder is not on your PATH yet. Add the line export PATH="$HOME/.local/bin:$PATH" to ~/.bashrc, and open a new terminal.

The Linux builds are linked with everything they need inside them, so the same file runs on Debian, Ubuntu, Fedora, Alpine or Raspberry Pi OS, old or new.

On macOS

The same steps work in the Terminal, with /usr/local/bin as the folder:

$ tar -xzf zeno-0.8.0-macos-arm64.tar.gz
$ sudo cp zeno-0.8.0-macos-arm64/zeno* /usr/local/bin/
$ xattr -d com.apple.quarantine /usr/local/bin/zeno
$ zeno --version

The xattr line is needed once. A program downloaded with a browser is held back by macOS until Apple has signed it, and Zeno is not signed; the line tells macOS that you trust this one.

On Windows

Unzip the file: right-click it in Explorer and choose Extract All. Make a folder for programs of your own, such as C:\Tools, and move zeno.exe (and zeno.wasm) into it. Then put that folder on the PATH: open the Start menu, type environment variables, choose Edit environment variables for your account, select Path, press Edit and New, and type the folder. A new Command Prompt or PowerShell window then finds it:

> zeno --version
zeno 0.8.0

Windows may warn that the program is from an unknown publisher, for the same reason as on macOS. More info, then Run anyway, lets it start.

Checking the download

Beside the files on the releases page is SHA256SUMS.txt, with the fingerprint of each one. To be sure that the file you have is the one that was built:

$ sha256sum --check --ignore-missing SHA256SUMS.txt
zeno-0.8.0-linux-x86_64.tar.gz: OK

On macOS the command is shasum -a 256 -c, and in PowerShell Get-FileHash prints a file’s fingerprint to compare by eye.

1.4 What else you may need

zeno run, check, test, format and the language server need nothing more. Three commands hand work to programs of other people:

  • zeno build writes C and gives it to a C compiler: the first of cc, gcc and clang that it finds, or the one the variable CC names. On Linux, install gcc or clang from the system’s packages; on macOS, xcode-select --install; on Windows, the installer offers one (Compiling). Zeno 0.1.0 looks for cc only, so on Windows it wants set CC=gcc first.

  • zeno build --llvm needs clang.

  • zeno fetch needs git, to get packages that live in other people’s repositories (Packages).

1.5 Building it from source

To build Zeno yourself you need:

  • Rust, with its build tool cargo. The usual way to get both is rustup, from https://rustup.rs. Zeno uses no libraries beyond Rust itself, so nothing else is downloaded when it is built.

  • git, to get the source.

Zeno is built and tested on Linux, macOS and Windows, with the same steps on each. Get the source and build it:

git clone https://github.com/zeno-src/zeno-lang
cd zeno-lang
cargo build --release

The finished program is target/release/zeno. To use it from any folder, either put that folder on your PATH, or let cargo copy the program into its own folder of programs, which rustup has already put on your PATH:

cargo install --path .

For web pages, build zeno.wasm as well. It is the same compiler, built for a browser:

rustup target add wasm32-unknown-unknown
cargo build --release --target wasm32-unknown-unknown

Check that it works:

$ zeno --version
zeno 0.9.0

If you want to be sure that the compiler you built is a good one, run its own tests. There are several hundred of them, and each program in them is run by every engine and built every way Zeno can build it:

cargo test --release

1.6 Your first project

zeno new makes a folder with a small program in it, ready to run:

$ zeno new greeter
Made the program `greeter` in greeter/
  zeno.package   the name of the program, and the packages it needs
  main.zeno      the program
  greeting.zeno  a module, with a test
Run it with `zeno run greeter/main.zeno`, and its tests with `zeno test greeter`.
$ zeno run greeter/main.zeno
Hello, world, from greeter.
$ zeno test greeter
greeter/greeting.zeno
  ok      hello says who it greets

1 test: 1 passed, 0 failed.

Three files were made. main.zeno is where the program starts. greeting.zeno is a module, a second file of the program, with a test at its end. zeno.package names the program and, later, the packages it needs. You will meet each of them properly: modules in Programs in Several Files, packages in Packages, and tests in Testing. For now, a program can be a single file with any name.

1.7 The commands

Everything Zeno does is a word after zeno. These are the ones you will use most; The zeno Command has all of them with every option.

Command What it does
zeno run file.zeno Check the program, and run it if there is nothing wrong
zeno check file.zeno Only check it, and report every mistake
zeno test Run the tests written in the files of a folder
zeno build file.zeno Compile it to C, and then to a program of its own
zeno format file.zeno Lay the file out the one way Zeno lays programs out
zeno new name Make a new program in a new folder
zeno fetch Get the packages a program needs
zeno lsp The language server that an editor starts

1.8 An editor

Any editor that can save plain text will do. Zeno files end in .zeno and are UTF-8 text. The Zeno repository has colours and setup for VS Code, Vim, Neovim and Helix in its editors folder, and zeno lsp lets those editors show mistakes as you type, jump to where a name was declared, show a name’s type, and lay the file out when you save it. The Tools shows how to set each of them up.

  1. Run zeno --help and read the list of commands. Which ones need a C compiler?

  2. Change the text that greeting.zeno gives back, and run zeno test greeter again. Read what a failed test prints, then change the test so that it passes.

  3. Run zeno new 2fast and zeno new while. What does Zeno say, and what does it suggest instead?
