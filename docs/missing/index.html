What Zeno does not have yet, and what to do about each

This page builds nothing. It is the whole list of what Zeno is still missing, in the order it should be built, with a recommendation for each item. It was written on 2026-11-18, against main after 0.5.1.

The list comes from three places:

  1. The limits Zeno wrote down itself. Chapter 11 of decisions.md and appendix G of the book, "What Zeno Does Not Have Yet". Each one was tried again on today's compiler for this page.
  2. What the README promises and has not delivered. The table "One language, every job" names C in both directions, async and await, fast arrays, operator overloading, and mobile.
  3. What C, C++, Python, JavaScript, Java, Rust and Go have that neither of the first two mentions. Each was tried as a small program, to see what Zeno says today.

Zeno is for firmware first, so what a board needs is weighed above what a server needs.

Will adding these change what works today?

No. Every item below is refused today with a message, or is a name that does not exist yet. No program that is accepted now uses any of them, so allowing one later changes the meaning of no program. That was the test for putting a limit on the list in the first place (11.6).

What each one costs is work, and the work is wide. A new built-in function is written for the interpreter, the VM, the C runtime, the LLVM build and fifteen targets. That is why the first item below is the one that makes the others cheap. And nothing may make a program that does not use it slower or larger: speed is compared before every release (release.md).

Items 1 to 8 are built, and went out in 0.7.0. How items 9 to 14 are to be built, part by part, with the ways of writing each that were weighed, is in plan-9-14.md. Items 9 to 12 are being built in full, and of item 13 the tests of a compiled program and the message on assert. The other tools of item 13 and the whole of item 14 are put off: their designs are in the plan, ready for when they are taken up.

Calling C from Zeno belongs between 7 and 8. It is being built elsewhere, as the third version of the bridges to other languages, so it is not on this list. What matters for firmware is that it works in zeno build --firmware, and not only in zeno run: a vendor's HAL is C.

Another language's code written in a .zeno file was not on this list either. It was asked for on 2026-11-23, in place of making Zeno a superset of the big languages, and is built for 0.9.0: an inline c, inline python or inline node block (inline.md, chapter 61). A block of C is part of the program's C in every build that writes C, firmware included. What it leaves for later is at the end of that page. zeno convert rewrites a file of Python or of C as Zeno and keeps what it cannot read in a block (convert.md, chapter 62; convert-c.md, chapter 63). TypeScript and JavaScript are the next languages it is to read.

Every journey is halfway done. Forever.

The runner has closed 0 of 1 halves
