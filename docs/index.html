How the compiler works

Zeno is written in Rust with no dependencies, and each stage has a walkthrough. Read them in order to see a language being built, from the first token to LLVM IR. Most end with things to try.

The front end

From text to a checked program.

  • How the lexer worksThe lexer is the first stage of the compiler. It turns a string of characters into a list of tokens, the words of the language. Every later stage works with tokens and never looks at raw characters again.
  • How the parser worksThe parser is the second stage. The lexer gave us a flat list of tokens; the parser works out how they nest and builds a syntax tree.
  • How the type checker worksThe type checker is the fourth stage. It reads the syntax tree and finds mistakes without running the program: a misspelt name, a str where an int was promised, a match that forgets a case, a value that might be none used as if it were not.

The engines

Four ways to run the same program.

  • How the interpreter worksThe interpreter is the third stage, and the first one that makes a program do something. It takes the syntax tree from the parser and runs it directly.
  • How the bytecode VM workszeno run has a second engine. With --vm it does not walk the syntax tree. It compiles the program to bytecode, a flat list of small instructions, and runs that.

Firmware and hardware

Errors as values, pins, inputs, a serial port and an ADC, sized numbers, bytes and units.

  • A serial portA serial port is how a board talks: to a terminal on a desk, to a GPS module, to a modem or to another board.
  • Reading a voltage: an analog pinMost of what a board measures arrives as a voltage on a pin: a potentiometer, a thermistor, a battery through two resistors, a current through a shunt. The board's converter (its ADC) turns that voltage into a number, and Zeno hands it over with its unit.

  • f32: a float of 32 bitsMost boards with a float unit, a Cortex-M4F, an M33 or an ESP32, have one of 32 bits. A float in Zeno has 64, and on those boards every float sum is done in software. f32 is a float of 32 bits, as C's float: about 7 digits, sums done by the board's…
  • u64: a whole number of 64 bits with no signAn int in Zeno has 64 bits and a sign, so it reaches about 9.2e18. A hash, a random generator, a 64-bit register or a counter of microseconds wants all 64 bits and no sign: 0 to 18446744073709551615. That is a u64, as C's uint64_t.
  • A list of a fixed lengthA buffer in firmware nearly always has a size that is known when the program is written: a frame of 8 bytes, a block of 512, a ring of 64. list[u8, 64] is a list that always has 64 items.
  • Bytes from and to a fileA firmware image, a capture from a logic analyser, a record a board wrote to its flash: none of them is text, and files.read refuses them (FileError: logo.png does not hold text). Two functions read and write a file as its bytes, each byte a u8 in a list[u8].
