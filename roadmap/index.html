Roadmap

Where Zeno stands

Zeno 0.8 is out: a function gives several values, enums and interfaces take a type, a block puts back what it opened, and a program is built for a board in one step, reads the board and calls C; zeno build --target writes it in fifteen other languages, zeno build --fast makes it as fast as C and Rust, and a program can choose how its memory is freed. The goal is one language for every job you would reach for C, C++, Python, JavaScript, Java or Rust to do. Each use case arrives with a piece of the compiler. This is the order they have come in, and the order the rest will.

Done

66 stages, each with a walkthrough. Every test program is run on all four engines and must print the same.

  1. LexerSource text becomes tokens.
  2. ParserTokens become a syntax tree.
  3. Interpreterzeno run walks the syntax tree.
  4. Type checkerGradual types: checked where written, worked out where left out.
  5. Compile to CThe whole language, as portable C.
  6. Garbage collectorA small mark-and-sweep collector in the compiled program.
  7. Errors as values--firmware: no setjmp, every caller tests.
  8. Owned valuesFreed at a line you can point to.
  9. No collector--no-collector leaves the collector out.
  10. Bytecode VMzeno run --vm, two to three times as fast.
  11. LLVM backendzeno build --llvm, with every flag.
  12. Board and timePins, sleep and now, on a simulated board.
  13. Sized numbersu8 to i32 and the bit operators.
  14. Genericsclass Stack[T], one compiled copy per type.
  15. A fixed memory poolNo malloc in a firmware build.
  16. Kept textText that is built and kept, with no collector.
  17. Statement-owned valuesA list nobody keeps is freed by its statement.
  18. One ownerWhoever receives a value owns it, with no collector.
  19. Enums, none, closures and errors with one ownerThe whole language builds with no collector.
  20. Memory by handunsafe { }, raw pointers, allocate, free and registers.
  21. An audit for clarityEvery feature checked: a parameter looks, and take takes.
  22. Text and listsfind, slice, sort, join and more.
  23. Files, input and argumentsimport files, input() and import program.
  24. More mathsAngles, logarithms, powers and rounding in math.
  25. Dictionariesdict[str, int], written ["a": 1].
  26. Programs in several filesimport sensors, and folders as modules.
  27. privateWhat a module keeps to itself.
  28. InterfacesA type says what it can do, and the checker holds it to that.
  29. Packageszeno.package, and code shared between programs.
  30. Teststest, assert and zeno test.
  31. Starting a programzeno new.
  32. The formatter and the language serverzeno format, and an editor that knows Zeno.
  33. The gaps programs found+= and a format on a quantity.
  34. Version 0.1Every provisional decision read again. The list is done.
  35. A program in a web pageimport web and zeno build --web.
  36. InstallersA setup program for Windows, one line for macOS and Linux, and packages for apt, pacman, snap, flatpak and Homebrew.
  37. A page that does moreEvents, styles, a canvas, timers and the network.
  38. A playgroundWrite and run Zeno in the browser, with nothing installed.
  39. What 0.1 left, taken upmin and max on quantities, zeno test --only, field hover.
  40. JSONjson.parse and json.write.
  41. Owners and the fast build (0.3, 0.4)--owned, a program with no collector, and zeno build --fast, as fast as C and Rust.
  42. Other languages (0.5)zeno build --target: JavaScript, TypeScript, Python, PHP, Go, Java, C#, C++, Rust, a web page and WebAssembly, each printing what zeno run prints.
  43. Four more languages (0.5.2)zeno build --target for Lua, Ruby, Dart and Kotlin: fifteen in all.
  44. A registry of packages (0.5.2)needs units at "v1.2.0" finds a package by its name. The registry is a git repository with no server; zeno search lists it and zeno publish puts a package in.
  45. The libraries of other languages (0.5.2)import python, import node and import java: the packages of pip and npm, and any jar, used as they are.
  46. Starting another program (0.5.2)program.run gives another program its words as a list, waits, and says how it ended.
  47. The least C (0.5.2)zeno build --minimal: only the C the program needs, with no checks, for a program that is already correct.
  48. A library written in Zeno (0.5.2)Six more functions of math and the module random, written once in Zeno and the same in every engine, build and target.
  49. Reading a board (0.6)input_pin, serial and analog_pin: a button, a serial port and a voltage, in every engine and every C build.
  50. The numbers firmware uses (0.6)f32, u64, list[u8, 64], bytes kept one to a byte, enum cases with numbers, and V * A is W.
  51. Calling C (0.6)import c: any library of C, and of Go and Rust through their C interface, from zeno run and from every C build.
  52. Four more languages' libraries (0.6)import ruby, import php, import lua and import csharp.
  53. Ending a program (0.6)program.exit, program.environment and program.warn.
  54. A PWM signal, a steady beat and interrupts (0.7)pwm_pin(9, 1 kHz), ticker(10 ms) and button.interrupt(falling): the three things the board module lacked.
  55. One step to a board (0.7)zeno build --board: a board is a folder that names its compiler, flags and linker script, and Zeno types the one long command. Two boards come with it, both an ARM Cortex-M3 that QEMU emulates.
  56. A board that prints by itself (0.7)A board's header brings four functions, and nothing of the program goes through the C library: hello in 936 bytes of flash.
  57. A float with no C library (0.7)A number with a fraction is made into text, and read from text, by Zeno itself, with whole numbers and exactly. It saves 28 KB of flash on a Cortex-M3.
  58. A C compiler that is neither GCC nor Clang (0.7)The few things a build asked of GCC and Clang by name are written a second time in plain C. tcc builds every example.
  59. More with no collector (0.8)raises in a function type, a function that is kept, a method as a value, take in front of a field, a dict that owns its values and a function inside a function, in every build. What is still refused is in one table.
  60. Several values (0.8)-> (int, str), let q, r = divide(7, 2) and a, b = b, a, in every engine, build and target.
  61. Generic enums and interfaces, and bounds (0.8)enum Maybe[T], interface Source[T], and largest[T is Ordered], which says what a type must be.
  62. Cleaning up when a block ends (0.8)An owned class that is Resource has its release run on every way out of the block that holds it.
  63. Folders and files in pieces (0.8)files.list, files.make_folder and files.join, and a file read line by line with files.read_from and written with files.write_to.
  64. Tests of a compiled program (0.8)zeno test --build runs a program's tests in the program C or LLVM makes of it, and an assert can say why it matters.
  65. Another language in a Zeno file (0.9, not released yet)inline c { }, inline python { } and inline node { }: code of another language kept as it was written, and called. A block of C is part of the program's C in every C build, and holds assembly too.
  66. A file of Python written as Zeno (0.9, not released yet)zeno convert shop.py writes shop.zeno: what it can say in Zeno as Zeno, the rest kept in an inline python block, so that what it writes always runs and prints what the Python printed.

Coming

In order, from the list of what Zeno lacks. A change to the syntax can still come before 1.0.

  • NowA file of C written as Zenozeno convert for C, with what it cannot read left in an inline c block.
  • NextOn a real boardEverything the board module has was tried on two emulated boards. No program of Zeno's has run on real hardware yet.
  • PlannedToolsLines of the program in a debugger, completion and rename in the editor, and a prompt to try things at.
  • PlannedTasks, async and awaitSeveral things at once: servers and networking.
  • PlannedCalled from CA Zeno function handed to C, and to the other languages, for callbacks.

Every journey is halfway done. Forever.

The runner has closed 0 of 1 halves

Zeno of Elea said Achilles can never catch the tortoise: first he must cover half the distance, then half of what is left, without end. It suits a compiler that will always be almost finished. The bar at the top of each page works the same way.
